### Design Concerns
1. **[Design Soundness] ImageRetentionCallback vs function_call format**: The Anthropic Responses API adapter uses `function_call`/`function_call_output` types, while ImageRetentionCallback (CUA SDK) may only process `computer_call_output` items. This means the apiMessages may show ALL screenshots instead of just the 3 most recent — defeating the purpose of showing "CUA-processed payloads." Need to verify how ImageRetentionCallback interacts with the Anthropic adapter.

2. **[Design Soundness] apiMessages size at scale**: Each apiMessages snapshot contains the full message list (~244 items at step 25). By step 500, this could be 2000+ items per snapshot × 500 steps = massive transcript file. Consider storing only new messages since last snapshot, or diffing.

3. **[Real-World Behavior] Only latest run has apiMessages**: Expected (feature was added after earlier runs), but means cross-run replay won't have apiMessages for historical sessions. This is fine — apiMessages are for observability, not replay.
