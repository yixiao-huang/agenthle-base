### Design Concerns
1. **ToolLoggingCallback only covers function_call, not computer_call** (Design Soundness) — CUA's `on_computer_call_start/end` hooks exist but aren't used. Computer calls (mouse/keyboard) are the majority of actions in a 50-step run. Adding computer_call logging would give full tool observability. *Low priority — computer actions are visible in trajectory files.*
2. **No `build_tools` test that verifies the 5-tool count** (Implementation Progress) — The test file tests `get_tool_summaries` and `ToolLoggingCallback` but not `build_tools` directly (it requires a CUA session). The integration test in `test_openclaw_agent_prompt.py` covers this indirectly. *Acceptable for now.*
3. **Plan doc references are slightly off** (Code Quality) — Plan doc says `openclaw/src/tools/pi-tools.ts` in the module docstring but the actual path is `openclaw/src/agents/pi-tools.ts`. Minor inaccuracy in the docstring at tools.py:12.
