### Design Concerns
1. **[Minor, Design Soundness]** `_ensure_tool_adjacency` is a symptom-level fix. The root cause is that memory flush messages are logged between `computer_call` and its result in the transcript. A cleaner fix would be to batch-write tool call + result atomically. This is acceptable for now but should be tracked.
2. **[Minor, Design Soundness]** The `_unnest_tool_blocks` helper handles `computer_call_output` blocks using `tool_use_id` as the call_id key, but real computer_call_output blocks from the Responses API use `call_id`. The fallback `block.get("call_id", "")` handles this, but the `tool_use_id` path may never fire in practice.
3. **[Observation]** Empty text blocks in assistant messages are silently dropped (line 955: `if text:`), which is correct behavior — avoids sending empty `output_text` items.
