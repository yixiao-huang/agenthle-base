### Design Concerns
1. **[Critical — Implementation Progress]** The `_build_compacted_items` method references `compaction_result.kept_messages` which doesn't exist on `CompactionResult`. The fix is straightforward: `_compact_in_place` already has `all_messages` from `_extract_messages_for_compaction()` — pass `all_messages[compaction_result.first_kept_message_index:]` to `_build_compacted_items` as the kept messages.

2. **[Medium — Design Soundness]** The items list mutation pattern (`items.clear(); items.extend(compacted_items); new_items.clear()`) after compaction at lines 241-243 is correct architecturally but means the next `combined = items + new_items` will only contain compacted content. This matches OpenClaw's `replaceMessages()` behavior — confirmed good.

3. **[Low — Design Soundness]** After compaction, the task instruction is not re-injected into the items list (the `_build_compacted_items` method only adds summary + kept messages). In a long task, the agent may lose track of the original goal. OpenClaw handles this via persistent `instructions=` parameter which CUA also supports — the instructions are always present. Confirmed OK since `self.instructions` is set on the `ComputerAgent` and injected by the SDK separately from the message list.
