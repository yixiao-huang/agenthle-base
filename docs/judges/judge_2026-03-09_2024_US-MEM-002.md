### Overall Assessment

The MemorySearchTool implementation is a reasonable intentional simplification of OpenClaw's `createMemorySearchTool`, but there are 4 meaningful deviations worth flagging: the `query` vs `keywords` parameter shape difference is the most significant design divergence, the missing `minScore` parameter is a gap that will matter when hybrid search lands, error handling returns exceptions instead of structured unavailable results, and the result format drops structured metadata in favor of plain text lines.

#### Deviation 1: `keywords: list[str]` vs `query: string` (INTENTIONAL but undocumented)

**OpenClaw** (`memory-tool.ts:13-17`):
```typescript
const MemorySearchSchema = Type.Object({
  query: Type.String(),
  maxResults: Type.Optional(Type.Number()),
  minScore: Type.Optional(Type.Number()),
});
```

**TinyClaw** (`memory/tools.py:33-46`):
```python
"keywords": {
    "type": "array",
    "items": {"type": "string"},
    "description": "List of keywords to search for...",
},
"max_results": { "type": "integer", ... },
```

- OpenClaw takes a single `query` string; the search backend handles tokenization, FTS5 MATCH parsing, and embedding.
- TinyClaw takes `keywords: list[str]` and does per-keyword substring matching in `MemoryStore.search()`.
- This is an intentional simplification for Phase 1 (keyword-only search), but it creates an **API break when hybrid search (US-MEM-006) lands**. Hybrid/semantic search needs a single query string for embedding, not a pre-split keyword list. The migration path is either: (a) join keywords into a query string at the tool level, or (b) add a `query` parameter and deprecate `keywords`.
- **Impact**: Medium. The agent learns to use `keywords: [...]` and will need re-prompting when the API changes for hybrid search.
- **Recommendation**: Add a `query` alias now (single string, tool splits on whitespace internally), and mark `keywords` as the keyword-only shorthand. This way the API is forward-compatible with US-MEM-006. *Rubric: Design Soundness.*

#### Deviation 2: Missing `minScore` parameter (GAP)

OpenClaw has `minScore: Type.Optional(Type.Number())` with `DEFAULT_MIN_SCORE = 0.35` (from `memory-search.ts:92`). TinyClaw has no score filtering -- every line with any keyword match (score >= 1.0) is returned.

- For Phase 1 (substring matching), this is acceptable since scores are integer counts (1, 2, 3...) and a minimum of 1 is implicit.
- For US-MEM-SQL (FTS5 + BM25) and US-MEM-006 (hybrid), `minScore` becomes essential to filter low-quality results that waste context tokens.
- **Impact**: Low now, medium later. The parameter should be added when US-MEM-SQL lands.
- **Recommendation**: Add `minScore` as optional parameter in US-MEM-SQL story, not now. Document this as a known gap. *Rubric: Design Soundness.*

#### Deviation 3: Error handling returns exceptions vs structured unavailable result (INTENTIONAL SIMPLIFICATION)

**OpenClaw** (`memory-tool.ts:63-96`): On failure, returns a structured JSON object:
```typescript
return jsonResult({
  results: [],
  disabled: true,
  unavailable: true,
  error: reason,
  warning: "Memory search is unavailable...",
  action: "Check embedding provider configuration...",
});
```

**TinyClaw** (`memory/tools.py:51-53`): On missing/empty keywords, raises `ValueError`:
```python
if not keywords:
    raise ValueError("'keywords' must be a non-empty list of strings")
```

- OpenClaw's graceful unavailability response is designed for a production assistant where the agent needs to inform the user. TinyClaw's ValueError is fine for a benchmark agent where a crashed tool call is immediately visible in trajectory logs.
- However, if `MemoryStore.search()` itself throws (e.g., filesystem error), the exception propagates unhandled through `call()`. OpenClaw wraps the search call in try/catch.
- **Impact**: Low. In practice, `MemoryStore.search()` is unlikely to throw in normal operation.
- **Recommendation**: Add a try/except around `self.store.search()` that returns a friendly error string instead of letting the exception propagate. This matches the pattern already used by MemoryGetTool and MemoryWriteTool. *Rubric: Code Quality.*

#### Deviation 4: Result format -- plain text lines vs structured JSON (INTENTIONAL SIMPLIFICATION)

**OpenClaw** returns structured JSON with `results`, `provider`, `model`, `fallback`, `citations`, `mode` fields. Each result has `path`, `startLine`, `endLine`, `snippet`, `score`, `citation`.

**TinyClaw** (`memory/tools.py:61-64`) returns plain text:
```python
lines.append(f"[{r.file_path}:{r.line_number}] (score {r.score}) {r.content}")
return "\n".join(lines)
```

- This is a reasonable simplification for the CUA agent which processes text, not JSON. The CUA ComputerAgent treats tool results as text strings in conversation context.
- However, returning plain text means losing structured data (startLine/endLine range, score as number vs string). If downstream processing needs to parse results, it has to regex the formatted string.
- **Impact**: Low. The agent consumes text; plain text is fine.
- **Recommendation**: No change needed. This is a justified simplification. *Rubric: Design Soundness.*

### Design Concerns

1. **`keywords` vs `query` API forward-compatibility** (Design Soundness): The `keywords: list[str]` parameter works for Phase 1 keyword search but creates an API migration burden for US-MEM-006 hybrid search, which needs a single query string for embedding. Either add `query` as an alias now, or plan an explicit migration in US-MEM-006. The OpenClaw reference uses `query: string` precisely because it supports both keyword (FTS5 MATCH) and semantic (embedding) modes through one parameter.

2. **Parameter naming: `max_results` vs `maxResults`** (Code Quality): TinyClaw uses snake_case (`max_results`) while OpenClaw uses camelCase (`maxResults`). Both are valid conventions, but the agent's LLM may use either casing since it sees both patterns in training data. The `_verify_json_format_args` in BaseTool does not normalize casing, so `maxResults` would be silently ignored (default 10 used instead). This is a minor robustness issue.

3. **Missing `disabled` / `unavailable` signaling** (Design Soundness): OpenClaw returns `{disabled: true, unavailable: true}` when memory search is not available, allowing the agent to inform the user. TinyClaw has no equivalent. If search fails (e.g., no memory files exist yet on first session), the agent gets "No memory results found" which is correct but doesn't distinguish "nothing matched" from "search is broken." For a benchmark agent this is acceptable, but could cause confusion in debugging.

### Prioritized Suggestions

1. **Add `query` parameter alias for forward-compatibility with hybrid search** -- Accept either `query: string` (split on whitespace internally) or `keywords: list[str]`. This avoids an API break when US-MEM-006 lands. *Impact: medium. Effort: low. Rubric: Design Soundness.*

2. **Add reference attribution docstring to MemorySearchTool** -- Follow the pattern already established by MemoryGetTool (line 69-74). Cite `openclaw/src/agents/tools/memory-tool.ts (createMemorySearchTool)` and document the intentional deviations (keywords vs query, no minScore, plain text results). *Impact: low. Effort: low. Rubric: Code Quality.*

3. **Add try/except around store.search() in MemorySearchTool.call()** -- Match the error handling pattern in MemoryGetTool and MemoryWriteTool. Return a friendly string like "Error searching memory: {error}" instead of propagating exceptions. *Impact: low. Effort: low. Rubric: Code Quality.*

4. **Update MemorySearchTool description to include task-scoped files** -- Current description mentions "MEMORY.md and daily logs" but search now also covers TASK_MEMORY.md and session-NNN.md files when task_id is set (added in US-MEM-TSK-S). *Impact: low. Effort: low. Rubric: Code Quality.*

5. **Plan `minScore` parameter for US-MEM-SQL** -- Not needed now (substring scores are integer counts), but essential when BM25/hybrid scores are continuous floats. Add as acceptance criterion to US-MEM-SQL. *Impact: low now, medium later. Effort: low to plan. Rubric: Design Soundness.*
