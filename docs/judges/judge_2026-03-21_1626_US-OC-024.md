### Design Concerns
1. **(Design Soundness)** The flush prompt treats task_memory as optional ("or target='task_memory' for strategies and insights"). In practice, the model takes the path of least resistance and only writes to session. OpenClaw has the same limitation (flush only points to daily files), but their heartbeat curation compensates — we have no equivalent.
2. **(Real-World Behavior)** The 33-step run produced a rich session log (game mechanics, navigation strategy, quest info) but none of this was distilled into task_memory. Future sessions won't benefit from these insights unless they happen to search session logs.
3. **(Design Soundness)** The memory flush handler (`_run_memory_flush` in memory_flush.py) currently only appends to session log programmatically. Even if the model calls `memory_write(target='task_memory')`, the flush handler's built-in behavior is session-only. Consider adding a programmatic task_memory update step.

### Prioritized Suggestions
1. **Strengthen flush prompt to mandate task_memory write** — Change MEMORY_FLUSH_PROMPT from "or target='task_memory' for strategies" to "FIRST write strategies/patterns to task_memory, THEN write observations to session log". The model needs a stronger directive. *Impact: high. Effort: low. Rubric: Real-World Behavior.*
2. **Add programmatic task_memory update in flush handler** — After the flush turn completes, if the model didn't write to task_memory, have the flush handler extract key insights from the session and write them programmatically. *Impact: high. Effort: medium. Rubric: Design Soundness.*
3. **Consider a consolidation step at task completion** — When the agent signals DONE, inject a consolidation turn that asks the model to review session logs and update TASK_MEMORY.md. This matches OpenClaw's heartbeat-driven curation. *Impact: medium. Effort: medium. Rubric: Design Soundness.*
