### Overall Assessment

US-OC-013's unit-level implementation is solid — budget-aware split, tool pairing repair, and recent turns preservation all work correctly in synthetic tests. However, the **budget-aware compaction is a no-op in real CUA runs** because `split_preserved_recent_turns()` treats all messages as "preserved" when there are fewer than 3 user-role messages in the transcript, which is the norm for CUA's computer-use pattern (one user message, then all assistant+tool turns).

### Design Concerns
1. **[CRITICAL — Design Soundness]** `split_preserved_recent_turns` is a faithful reproduction of OpenClaw's function, but OpenClaw operates in a multi-turn chat context (Telegram, Discord) where users send many messages. CUA's computer-use loop has ONE user message. The function needs to be adapted: count assistant turns (not user turns) or bypass the preserve logic entirely and let the budget loop operate on all messages.

2. **[HIGH — Real-World Behavior]** After compaction, the agent loses ALL context because: (a) all messages are "preserved" so nothing is summarized, (b) replay_messages is cleared after compaction, (c) the compaction summary is just "No prior history." The agent post-compaction correctly recalls memory via `memory_search` / `memory_get`, but the compaction pipeline itself provides zero value — it's just an expensive agent restart.

3. **[MEDIUM — Design Soundness]** The VM test shows compaction at step 35 and step 92. Between those (57 steps), the context goes from 1K back up to 41K. This matches expectations for a 50K window. However, the "compaction" at each trigger is doing nothing useful — it should be summarizing the older portion of the context. The fact that the agent still works is because of memory tools and CUA's `only_n_most_recent_images=3`, not because of compaction.

### Prioritized Suggestions

1. **Fix `split_preserved_recent_turns` for CUA message pattern** — Count assistant+tool turn pairs (not user messages) for the preserve count. In CUA, each "turn" is an assistant message + its tool result. Preserving the last 3 such pairs gives the agent immediate working context while allowing the budget loop to operate on older turns. *Impact: HIGH. Effort: LOW. Rubric: Design Soundness, Real-World Behavior.*

2. **Add fallback when all messages are preserved** — When `pruneable` is empty, the budget loop is unreachable. Add a fallback: if `preserved_tokens > available_for_kept`, treat the oldest N preserved messages as pruneable and summarize them. This ensures compaction always produces a useful summary. *Impact: HIGH. Effort: MEDIUM. Rubric: Real-World Behavior.*

3. **Add `MAX_RECENT_TURNS_PRESERVE` cap** — Cap `preserve_count` at 12 (matching OpenClaw) to prevent pathological cases where preserve_count exceeds message count. *Impact: LOW. Effort: LOW. Rubric: Code Quality.*

4. **Skip compaction when pruneable is empty** — If `split_preserved_recent_turns` returns no pruneable messages, skip the compaction entirely instead of rebuilding the agent with a "No prior history" summary. This avoids wasting an API call and losing context. *Impact: MEDIUM. Effort: LOW. Rubric: Real-World Behavior.*

5. **Add a CUA-specific integration test** — The existing unit tests use synthetic `_make_messages()` with alternating user/assistant roles. Add a test that builds messages matching real CUA output patterns (1 user, then N assistant+tool pairs) and verify the budget loop actually runs. *Impact: HIGH. Effort: LOW. Rubric: Implementation Progress.*
