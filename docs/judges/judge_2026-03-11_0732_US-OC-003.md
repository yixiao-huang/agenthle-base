### Design Concerns

1. **[Implementation] Agent can't run — `.name` AttributeError blocks all VM testing.** The `session._computer` object is a CUA Computer, not a BaseTool. The `tool_summaries` dict comprehension at line 88 crashes. This blocks not just US-OC-003 but all downstream stories. Fix: filter tools to only BaseTool instances for summaries, or hardcode Computer's description.

2. **[Design Soundness] Tool wiring is deferred to US-OC-007 but AGENTS.md already references tools.** AGENTS.md (lines 23-25) tells the agent to use `memory_search`, `memory_get`, `memory_write` — but these tools aren't registered with ComputerAgent. The agent will see instructions for tools it can't call. This creates a confusing gap. Consider wiring tools as part of US-OC-003 or at least documenting the gap.

3. **[Design Soundness] `memory_write` overwrite semantics for task_memory.** Writing to `task_memory` target overwrites the entire `TASK_MEMORY.md`. This is correct per design (curated knowledge), but the agent might accidentally destroy valuable content by overwriting with partial updates. Consider adding an `append` mode for task_memory or documenting the overwrite risk more prominently.

### Prioritized Suggestions

1. **Fix `.name` AttributeError in openclaw_agent.py** — Guard `tool_summaries` against non-BaseTool objects. Either filter `tools` to only BaseTool instances or use `getattr(tool, 'name', None)`. This unblocks all VM testing. *Impact: high. Effort: low. Rubric: Implementation Progress, Real-World Behavior.*

2. **Wire memory tools into agent tool list** — Even though US-OC-007 is the formal story for this, US-OC-003 cannot demonstrate value without the tools being registered. Add `MemorySearchTool(memory_store)`, `MemoryGetTool(memory_store)`, `MemoryWriteTool(memory_store)` to the tools list at line 87. *Impact: high. Effort: low. Rubric: Implementation Progress, Real-World Behavior.*

3. **Remove `allow_overwrite=True` or isolate legacy tools** — The `allow_overwrite` flags mask a real conflict between legacy `memory/tools.py` and new `openclaw/memory.py`. If both are importable, the last-imported wins silently. Either remove legacy tools from the package path or gate their import. *Impact: medium. Effort: low. Rubric: Code Quality.*

4. **Add acceptance criterion: "memory tools appear in agent's registered tools during VM run"** — Current ACs only test code structure, not runtime registration. Add: "After run_magic_tower.sh, trajectory logs show memory_search/memory_get/memory_write in available tools." *Impact: medium. Effort: low. Rubric: Implementation Progress.*

5. **Strengthen path traversal check** — Replace substring `".." in file_path` with resolved-path containment check. Current check is fragile (false positives on legitimate `..` in names, though unlikely for `.md` files). *Impact: low. Effort: low. Rubric: Code Quality.*
