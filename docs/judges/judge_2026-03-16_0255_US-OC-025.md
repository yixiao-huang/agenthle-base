### Design Concerns
1. **[Critical — Design Soundness]** Flush check runs once per `agent.run()` call, not per individual agent turn. CUA's `ComputerAgent.run()` is an opaque async generator that handles multiple turns internally. The flush check at the top of the while loop only fires (a) before the first `agent.run()` where `current_tokens=0` → skip, and (b) after compaction where `reset_after_compaction()` sets `current_tokens=0` → skip. **Fix**: Move the `should_run_memory_flush` check + `_run_memory_flush` call INSIDE the `async for result in agent.run()` loop, right before the compaction check (line 378). At this point, `overflow_cb.current_tokens` is fresh from the just-completed step. The flush fires between steps (not between turns), but this is the closest CUA allows. Flush should break the agent.run() loop, run flush, and optionally not trigger compaction if tokens are still below 80%.

2. **[Medium — Design Soundness]** After `reset_after_compaction()`, `current_tokens` drops to 0 even though the post-compaction context still has tokens. The ContextOverflowCallback doesn't re-estimate until the next `on_llm_start` call. This means any check between compaction and the next step sees stale data. This is acceptable for compaction (which doesn't re-trigger at 0) but prevents flush from working.

3. **[Low — Code Quality]** The plan doc (`docs/plan/US-OC-005a-memory-flush-tracking.md`) was updated (line 102) to say flush runs "pre-turn" but the implementation doesn't actually achieve per-turn checking. The doc should note the CUA limitation.

### Prioritized Suggestions

1. **Move flush check inside `async for` step loop** — Place the `should_run_memory_flush()` check inside the `async for result in agent.run()` loop, between token tracking (line 330) and the compaction check (line 378). When flush triggers, break the loop with a `flush_triggered` flag, run `_run_memory_flush()`, but DON'T rebuild the agent (flush doesn't change the context). Then re-enter `agent.run()` in the next while iteration. *Impact: high. Effort: medium. Rubric: Design Soundness + Real-World Behavior.*

2. **Export and test `DEFAULT_MEMORY_FLUSH_RESERVE_TOKENS_FLOOR`** — Add to `__init__.py` exports and `__all__`. Add `test_default_reserve_tokens_value` to `TestMemoryFlushConstants`. *Impact: low. Effort: low. Rubric: Code Quality.*

3. **Fix stale test comment** — Update `test_triggers_when_above_threshold` comment from "threshold=96000" to "threshold=76000" (reflects new default reserve_tokens=20000). *Impact: low. Effort: low. Rubric: Code Quality.*

4. **Add public accessor for session state existence** — Replace `session_mgr._state is not None` with a public `session_mgr.is_initialized` property. *Impact: low. Effort: low. Rubric: Code Quality.*

5. **Consider separate flush-triggered break** — When flush fires inside the step loop, it could break and re-enter agent.run() WITHOUT compacting. This would match OpenClaw's pattern where flush is independent of compaction. Add a `flush_triggered` flag parallel to `compaction_triggered`. *Impact: medium. Effort: medium. Rubric: Design Soundness.*
