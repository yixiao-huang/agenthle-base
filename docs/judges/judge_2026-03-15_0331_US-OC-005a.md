### Design Concerns
1. **[Design Soundness]** OpenClaw resets `memoryFlushAt` and `memoryFlushCompactionCount` to `undefined` on `/new` and `/reset` (`session.ts:525-526`). Our `init_session()` loads existing state and preserves these fields. This means a flush from a previous run could prevent the first-run flush in the next run if compaction_count hasn't changed. **Mitigation**: This is likely fine in practice because `init_session()` doesn't reset `compaction_count` either (it's cumulative). The flush guard only triggers when `memory_flush_compaction_count == compaction_count`, so a new compaction in the new run will naturally allow a new flush. However, if US-OC-008 wiring expects a clean slate, consider adding `self._state.memory_flush_at = None; self._state.memory_flush_compaction_count = None` to `init_session()`.
