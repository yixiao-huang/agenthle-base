### Design Concerns

1. **PromptBuilder is a dead module** — The most critical gap is that `prompt.py` is complete and tested but never called. `openclaw_agent.py` still has the hardcoded string from before this story. Until the builder is wired in, the story's behavioral value (structured, configurable instructions reaching the LLM) is zero. The design doc's "How Tools Are Specified" section even gives the exact integration code. This should have been the capstone of the story — writing the module without wiring it is 80% done.

2. **AC/design-doc conflict creates false test failures** — Acceptance criteria #2 and #3 refer to `## Task Context` and `## Current Time` sections that the design doc explicitly decided to drop. If the AC is taken literally, the story fails on criteria that the implementation correctly does not meet. This ambiguity will confuse the `/ship` reviewer and future auditors. The fix is a one-line `/prd` update to sync AC with the design doc.

3. **No size-cap on `_build_project_context()`** — OpenClaw's bootstrap injection has hard limits (20K per file, 150K total) because unbounded context file injection is a known footgun: large `MEMORY.md` files will silently consume a huge fraction of the context window on every turn. Our implementation has no cap. For US-OC-001 this is acceptable (deferred to US-OC-008), but it needs to be explicitly tracked. If `MEMORY.md` grows to 50K chars and gets injected on every turn, context compaction will trigger far earlier than expected.

### Prioritized Suggestions

1. **Wire PromptBuilder into `openclaw_agent.py`** — In `perform_task()`, before creating `ComputerAgent`, add:
   ```python
   from .openclaw import PromptBuilder, PromptConfig, ContextFile
   tool_summaries = {tool.name: tool.description for tool in [session._computer, milestone_tool]}
   agents_md = (Path(__file__).parent / "openclaw" / "AGENTS.md").read_text()
   builder = PromptBuilder()
   instructions = builder.build(
       tool_summaries=tool_summaries,
       context_files=[ContextFile(path="AGENTS.md", content=agents_md)],
   )
   ```
   Then pass `instructions=instructions` to `ComputerAgent`. This is the exact integration described in the design doc. *Impact: high. Effort: low (< 15 lines). Rubric: Implementation Progress, Real-World Behavior.*

2. **Fix stale acceptance criteria in prd.json** — Run `/prd` to update AC #2 (remove "includes current time/timezone") and AC #3 (fix section names: `## Memory` → `## Memory Recall`, remove `## Task Context` and `## Current Time`, add `# Project Context`). Also add a missing criterion: "PromptBuilder.build() output is passed as `instructions=` in ComputerAgent in `openclaw_agent.py`". *Impact: medium. Effort: low. Rubric: Implementation Progress.*

3. **Add a TODO comment for size-cap deferral in `_build_project_context()`** — Add one line: `# TODO US-OC-008: add per-file and total char size caps (ref: openclaw bootstrap 20K/150K limits)`. This makes the known gap visible to future implementers without blocking this story. *Impact: low. Effort: trivial. Rubric: Design Soundness.*

4. **Narrow the lint AC scope** — The criterion `uv run ruff check .` always fails due to pre-existing debt in unrelated files. Change the scope to the story-owned paths: `uv run ruff check submodules/cua/libs/cua-bench/cua_bench/agents/openclaw/ tests/test_prompt_builder.py`. *Impact: medium (unblocks passing the lint criterion). Effort: trivial. Rubric: Implementation Progress.*

5. **Add a VM smoke test (5–10 steps) after wiring** — Once the builder is wired, run `run_magic_tower.sh 10` and verify the trajectory `api_start.json` shows the structured prompt (check for `## Identity` and `## Tools` in the instructions field). This is the minimum Level 2 check. *Impact: high (closes the behavioral gap). Effort: low. Rubric: Real-World Behavior.*
