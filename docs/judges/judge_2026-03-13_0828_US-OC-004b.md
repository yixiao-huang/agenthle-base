### Design Concerns
1. **Mixed format transcript** (Design Soundness) — The append-only JSONL file now contains both old-format (runs 1-9) and new-format (run 10+) entries. When the compaction pipeline (US-OC-006) processes this history, it needs to handle both `role:"toolResult"` and `role:"tool"`, both `type:"toolCall"` and `type:"function_call"`. **Fix**: Either add a normalization step in `load_history()` or document that downstream consumers must handle both formats.
2. **Screenshot paths are relative** (Design Soundness) — Screenshot content values like `trycua/cua-bench/.../turn_011/0071_screenshot_after.png` are relative paths. If the working directory changes between runs, these won't resolve. Consider using absolute paths from `_find_latest_screenshot()` (it already returns `str(path)` which should be absolute from `Path.rglob()`).
3. **No validation on role/type** (Code Quality) — `append_message()` accepts any role string without validation. This is deliberate (passthrough design) but means a caller typo won't be caught. Low priority given the caller is controlled code.
