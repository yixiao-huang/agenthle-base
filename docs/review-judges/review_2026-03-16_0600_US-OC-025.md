## Root Cause Summary

The flush check is at the **wrong granularity**. It sits at the top of the while loop (once per `agent.run()` call), but `overflow_cb.current_tokens` is:
- **0** on first iteration (no steps have run yet)
- **0** after compaction (`reset_after_compaction()` clears it)

So the check never sees a non-zero token count. The fix is to move it **inside** the `async for result in agent.run()` loop, where `overflow_cb.current_tokens` is fresh from the just-completed step.
